## Experiment 3: Hierarchical Step-Adaptive RSSI

### Aim

This experiment revises Derek's Point 4b into a simpler and more interpretable adaptive-window algorithm.

Instead of first classifying each window into several activity states, the algorithm directly asks whether the participant is low-motion over progressively shorter time windows. The goal is to use longer RSSI windows when step count suggests stable low movement, and shorter RSSI windows when the participant appears more active.

This remains a no-reference analysis. The results are interpreted by window choice, RSSI confidence, location transition frequency, and co-presence summaries.

### Scripts

Main algorithm:

```text
src/X001/forthphase_hierarchical_step_adaptive_rssi.py
```

Step-count diagnostic:

```text
src/X001/forthphase_step_threshold_diagnostics.py
```

### Step-Count Preprocessing

The raw step-count data are cumulative and irregularly sampled. To avoid treating missing step windows as zero movement, the cumulative step-count series was first interpolated onto a regular 1-minute timeline. Step increments were then calculated from this 1-minute series and aggregated to:

* 1-minute windows
* 5-minute windows
* 10-minute windows
* 30-minute windows

This makes the step-count summaries more comparable across window sizes.

### Algorithm

For each 1-minute timestamp and each role, the algorithm applies the following hierarchy:

```text
if 30min steps <= threshold:
    use 30min RSSI
elif 10min steps <= threshold:
    use 10min RSSI
elif 5min steps <= threshold:
    use 5min RSSI
else:
    use 1min RSSI
```

The tested thresholds were:

```text
1, 2, 5, 10 steps
```

The final selected threshold is:

```text
threshold = 10 steps
```

This is interpreted as a low-motion stability threshold rather than a strict no-movement threshold. Ten steps over 30 minutes is still very low activity, and this threshold gives a more useful adaptive behaviour than the stricter threshold of 5 steps.

### RSSI Availability Rule

RSSI is dense when available, but there are long no-detection periods. These long periods likely indicate that the bracelet is outside the home beacon coverage area, or that no room-level RSSI evidence is available.

Therefore, RSSI is not interpolated. If the selected RSSI window has no RSSI detection, the location estimate remains away or unmapped.

This conservative rule avoids smoothing short out-of-home periods into an indoor room estimate.

## Experiment 4: Low-Motion RSSI Clustering

### Aim

This experiment implements Derek's Point 4c:

> use automatic clustering on RSSI values during low-motion periods, then apply the cluster model to the full timeline.

The aim is to move beyond a strongest-beacon rule and test whether stable low-motion RSSI vectors form interpretable signal clusters.

This remains a no-reference exploratory method. The clusters are RSSI-derived signal states, not independently verified room labels.

### Script

```text
src/X001/forthphase_low_motion_rssi_clustering.py
```

### Method

The clustering workflow is:

1. Use the 4b uniformized step-count preprocessing.
2. Define low-motion training windows as `30min steps <= 10`.
3. Build 30-minute RSSI vectors using active metadata-mapped home beacons only.
4. Exclude external or inactive/unmapped beacons from clustering features.
5. Fill missing beacon RSSI values inside valid RSSI windows with `-100`.
6. Train separate KMeans models for SUBJECT and STUDY_PARTNER.
7. Test `k = 3, 4, 5, 6, 7, 8`.
8. Select k using silhouette score, while rejecting k values with very small clusters.
9. Apply the selected cluster model to all 30-minute windows with RSSI evidence.
10. Keep no-RSSI windows as away or unmapped.

### 4c Diagnostic and Interpretation

Derek noticed that some periods appear different between 4b and 4c, especially where 4b gives an unmapped or grey period while 4c gives a Bathroom-like result.

The current interpretation is:

* 4b is a direct window-level RSSI method.
* 4b chooses the RSSI window length using step count, then uses the strongest mapped beacon in that selected window.
* 4c is a learned RSSI signal-state method.
* 4c assigns each RSSI vector to a learned cluster, then interprets that cluster using its dominant mapped location.

Therefore, 4b and 4c are not doing exactly the same thing. A grey period in 4b should be interpreted as:

```text
away / unmapped / no mapped location estimate
```

It should not always be interpreted as complete absence of beacon visibility. Some grey 4b periods still contain RSSI samples, but those samples may not produce a clear mapped room under the direct strongest-beacon rule.

The diagnostic output is saved here:

```text
Results/X001/ForthPhase/Figures_0615/X001_0617_grey_to_blue_diagnostic.csv
```

The current diagnostic found 59 STUDY_PARTNER windows where:

```text
4b location = Unmapped
4c cluster location = Bathroom
4c has RSSI evidence = True
```

This suggests that 4c may over-generalise some ambiguous RSSI patterns into a dominant Bathroom-like cluster, especially for STUDY_PARTNER. This does not necessarily mean that 4c is invalid as a clustering method. It means that the clusters should be interpreted as repeated RSSI signal states rather than direct room-level location labels.

For this reason, 4c should remain exploratory. The main movement + RSSI location method is still 4b.
