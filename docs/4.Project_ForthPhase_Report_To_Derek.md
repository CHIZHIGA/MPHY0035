# Fourth Phase Progress Report: Home_X001 RSSI and Movement Analysis

## Context

This report summarises the current Fourth Phase work based on Derek's feedback from 2026-06-10.

The main aim of this stage is to investigate whether raw RSSI and movement data can be combined to estimate location and co-presence patterns in the Home_X001 dataset.

The analysis treats the two devices as:

| Folder | Analysis role |
|---|---|
| `LEFT_WRIST` | SUBJECT |
| `RIGHT_WRIST` | STUDY_PARTNER |

This mapping was confirmed using `subject_type` in `metadata_subject.json`.

The X001 dataset does not currently include independent reference location labels. Therefore, the results below should be interpreted as descriptive RSSI-derived estimates rather than validated location labels.

## Main Research Message

The key message of this stage is:

> RSSI provides the main spatial signal, while movement data can be used to decide how much temporal smoothing should be applied when estimating location.

In other words, RSSI is used to estimate the likely room or home-location state, while step count is used to decide whether the RSSI estimate should come from a short or long time window.

## 3. Movement-Adaptive RSSI Using Step Count

The next method used step count to adapt the RSSI window size.

The raw step-count data are cumulative and irregularly sampled, so the cumulative step series was first interpolated onto a regular 1-minute timeline. Step increments were then aggregated into 1-minute, 5-minute, 10-minute, and 30-minute windows.

The final adaptive algorithm uses the following hierarchy:

```text
if 30min steps <= 10:
    use 30min RSSI
elif 10min steps <= 10:
    use 10min RSSI
elif 5min steps <= 10:
    use 5min RSSI
else:
    use 1min RSSI
```

If the selected RSSI window has no RSSI detection, the window is kept as away or unmapped. I did not fill no-RSSI periods using a longer RSSI window, because this could incorrectly smooth short out-of-home periods into an indoor estimate.

### Why Threshold 10 Was Selected

I compared step thresholds of 1, 2, 5, and 10. Threshold 10 was selected as the practical low-motion threshold because it reduced excessive 1-minute window selection and increased the use of longer windows.

Window choice for threshold 5 vs threshold 10:

| Threshold | Role | 1min | 5min | 10min | 30min |
|---:|---|---:|---:|---:|---:|
| 5 | SUBJECT | 63.4% | 7.2% | 10.6% | 18.7% |
| 5 | STUDY_PARTNER | 43.8% | 11.4% | 15.0% | 29.9% |
| 10 | SUBJECT | 55.1% | 10.9% | 10.6% | 23.4% |
| 10 | STUDY_PARTNER | 36.8% | 8.8% | 18.9% | 35.4% |

Threshold 10 is therefore better for the intended purpose of producing a smoother movement-aware timeline during low-motion periods.

### Adaptive Co-Presence Summary

| State | Hours | Percentage of shared time |
|---|---:|---:|
| Same estimated location | 15.1 h | 8.8% |
| Different estimated locations | 55.8 h | 32.7% |
| SUBJECT home only | 14.8 h | 8.7% |
| STUDY_PARTNER home only | 36.2 h | 21.2% |
| Both away or unmapped | 48.9 h | 28.6% |

The adaptive method does not radically change the overall co-presence pattern compared with the fixed-window baseline. Its main value is methodological: it uses movement to decide when longer or shorter RSSI windows are appropriate.

## 4. Low-Motion RSSI Clustering

I also tested an exploratory RSSI-vector clustering method.

The idea was to use low-motion periods to learn stable RSSI signal states, then apply the cluster model to the full timeline.

The method:

1. Uses the same step-count preprocessing as the adaptive method.
2. Defines low-motion training windows as `30min steps <= 10`.
3. Builds 30-minute RSSI vectors using active mapped home beacons only.
4. Excludes external or inactive/unmapped beacons from clustering features.
5. Trains separate KMeans models for SUBJECT and STUDY_PARTNER.
6. Tests `k = 3, 4, 5, 6, 7, 8`.
7. Selects k using silhouette score, while avoiding very small clusters.

Both roles selected:

```text
k = 3
```

Cluster profile summary:

| Role | Cluster | Training windows | Predicted windows | Dominant beacon | Dominant location | Mean RSSI confidence |
|---|---:|---:|---:|---|---|---:|
| SUBJECT | 0 | 11 | 34 | 08E5 | Living | 0.668 |
| SUBJECT | 1 | 37 | 138 | 2501 | Other 1 | 0.682 |
| SUBJECT | 2 | 28 | 59 | 747F | Bedroom | 0.684 |
| STUDY_PARTNER | 0 | 97 | 140 | 747F | Bedroom | 0.883 |
| STUDY_PARTNER | 1 | 36 | 229 | D496 | Bathroom | 0.707 |
| STUDY_PARTNER | 2 | 41 | 56 | 747F | Bedroom | 0.928 |

The clusters are interpretable as repeatable RSSI signal states, but they should not yet be treated as direct replacements for room-level strongest-beacon estimates.

The clustering method gives a smoother timeline and higher RSSI confidence, but it also assigns many RSSI windows to a small number of dominant cluster locations. I therefore currently see it as an exploratory signal-state method rather than the main location method.

## Current Interpretation

My current interpretation is:

1. RSSI is still the primary spatial signal.
2. Fixed RSSI windows give a stable baseline, especially at 10 or 30 minutes.
3. Step count is useful for choosing the window length, because low-motion periods can use longer windows while more active periods can use shorter windows.
4. The adaptive method is valuable because it directly combines movement and RSSI, even though the broad co-presence summary remains similar to the RSSI-only baseline.
5. RSSI clustering is useful as an exploratory method for stable signal states, but it is less directly interpretable as room-level location.

## Limitations

The main limitation is that X001 currently has no independent reference location labels. Therefore:

* I cannot assess whether one method is objectively better in terms of true room location.
* I can compare methods by stability, confidence, transition frequency, and co-presence patterns.
* The metadata beacon-location mapping is useful for interpretation, but it is not an independent validation label.
