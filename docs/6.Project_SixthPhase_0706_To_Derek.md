# Sixth Phase 2026-07-06 Update: Quantifying Stair Transitions

## Context

This update follows Derek's 2026-07-05 suggestion to move from location estimation toward behavioural metrics. The first metric explored here is stair use:

```text
number of stair ascents / descents
time taken to ascend / descend
```

The analysis uses the same 80-hour single-user two-floor home dataset:

```text
Data/New data- 80 hour single user/559662
```

## Aim

The aim is to test whether the pressure-derived floor timeline can be converted into a behavioural stair-transition metric.

The previous Sixth Phase work showed that:

* pressure can separate the two floor levels;
* the bracelet pressure can be compared with beacon pressure groups to infer 1F versus 2F;
* most pressure-derived floor transitions have ACC support;
* pressure is therefore a plausible main signal for identifying stair-transition candidates.

This section turns those floor transitions into stair ascent/descent events and estimates how long the stair movement appears to take.

## Step 1: Stair Transition Candidates

The first step uses the 5-minute pressure-derived floor timeline to identify floor switches:

```text
1F -> 2F = ascent
2F -> 1F = descent
```

These events come from the pressure floor signal, not from RSSI. RSSI/beacon switching is useful context, but the stair-transition candidates are defined by pressure-derived floor changes.

The candidate table is:

```text

```

The event timeline is:

![Pressure-derived stair ascent/descent events](../Results/SixthPhase/QuantifiedMetrics/new80h_stair_events_timeline.png)

The pressure-derived floor timeline produced:

| Metric | Count |
|---|---:|
| Total stair-transition candidates | 24 |
| Ascents | 12 |
| Descents | 12 |
| ACC-supported candidates | 20 |
| ACC-unsupported candidates | 4 |

The four ACC-unsupported candidates were retained rather than removed. This is because pressure is the main stair-transition signal, while ACC is supporting evidence. Some unsupported cases occur close to window boundaries or have short refined pressure ramps, so a lack of ACC support does not necessarily mean the stair event is false.

## Step 2: Refined Stair Duration

The initial 5-minute floor timeline is too coarse to estimate the true time taken to climb or descend stairs. A 5-minute value should be interpreted only as a pressure/ACC evidence window, not as the actual stair duration.

To estimate a more realistic stair duration, I returned to the higher-resolution bracelet pressure and ACC data:

* bracelet pressure is sampled at approximately 30-second resolution;
* ACC magnitude is also available at approximately 30-second resolution;
* pressure was cleaned using the same pressure-cleaning approach as the previous Sixth Phase analysis;
* each pressure-derived floor shift was examined in a local window around the shift time;
* the refined stair duration was estimated from the 10%-90% pressure ramp;
* ACC was then summarised within the refined pressure-ramp interval.

The refined duration table is:

```text

```

The summary table is:

```text

```

## Event Quality Rule

For the behavioural duration summary, I used a pressure-based validity rule:

```text
valid stair event =
pressure ramp direction matches ascent/descent direction
AND pressure ramp delta is not too small
AND refined duration is not longer than 3 minutes
```

ACC support is not used as a deletion criterion. Instead, it is kept as a confidence annotation.

This is important because some ACC-unsupported events still have a clear and plausible pressure ramp. These are better described as:

```text
pressure-valid, ACC-unsupported
```

rather than discarded.

## Refined Duration Results

Using the pressure-based validity rule:

| Metric | Count |
|---|---:|
| Valid stair events | 14 / 24 |
| Valid ascents | 6 |
| Valid descents | 8 |

The mean duration by stair direction was:

| Direction | Valid events | Mean duration |
|---|---:|---:|
| Ascent | 6 | 1.08 min |
| Descent | 8 | 0.81 min |

Only the mean is used for interpretation here because the sample size is small.

## Interpretation

The refined results suggest that stair ascent may take slightly longer than stair descent for this participant:

```text
mean ascent duration  = 1.08 min
mean descent duration = 0.81 min
```

This is consistent with the expectation that going upstairs is usually more physically demanding than going downstairs. However, the number of valid events is small, so this should be treated as a preliminary descriptive finding rather than a strong conclusion.

A careful wording would be:

> In the pressure-valid stair-transition subset, ascent events took slightly longer than descent events on average. This may indicate that stair ascent is the more demanding mobility behaviour for this participant, although the sample size is small and the result should be interpreted descriptively.

## Notes on ACC Support

ACC is useful as supporting evidence, but it should not be used as the sole inclusion/exclusion rule.

The refined analysis showed that some events have:

```text
clear pressure ramp
reasonable duration
but weak ACC support
```

These cases may occur because:

* the pressure ramp is short;
* the ACC sampling interval is coarse;
* the participant's wrist movement during stair use is limited;
* the stair event occurs near the edge of a 5-minute ACC support window;
* the ACC threshold may be conservative.

Therefore, the most defensible interpretation is:

```text
pressure = main signal for stair transition and duration
ACC = confidence/support signal
```

## Current Conclusion

This analysis shows that pressure-derived floor transitions can be converted into behavioural stair-use metrics. The method identifies 24 candidate stair transitions and 14 pressure-valid refined stair events. Among these valid events, ascent took slightly longer than descent on average.

This supports Derek's suggestion that the sensor fusion pipeline can move beyond location estimation and begin quantifying behavioural mobility metrics.

## Step 3: Low-Motion Long-Stay / Sleep-Location Candidate

Before moving fully into room transitions, I also tested whether the same 5-minute
pressure-floor-aware RSSI timeline can identify a likely sleep location.

The motivation is that sleep or bedroom occupancy should have two properties:

* low bracelet movement;
* a long, regular stay during evening/night hours, where short beacon switches
  may still occur because RSSI is noisy.

For this exploratory analysis, I used:

```text
low-motion window = acc_magnitude_std_clean <= 0.010
night search window = 18:00 to 10:00 local time
location source = pressure_floor_bruteforce_rssi_beacon
minimum candidate episode length = 60 minutes
dominant beacon share threshold = 60%
```

## Step 4: ACC-Supported Room Transition Metrics

I then quantified room/beacon transitions using the pressure-floor-aware RSSI
timeline.

The aim is to focus on awake or moving periods, since room transitions are only
expected to be meaningful when the participant is active. I therefore used the
opposite of the low-motion rule:

```text
awake/motion window = acc_magnitude_std_clean > 0.010
```

The location source was the pressure-floor-corrected RSSI result:

```text
pressure_floor_bruteforce_rssi_beacon
```

A room transition was counted when the corrected beacon label changed between
adjacent 5-minute windows. A transition was marked as ACC-supported if the
transition window, the previous window, or the following window was an
awake/motion window.

## Updated Interpretation

The quantified metrics now cover three behaviours:

* stair use, derived mainly from pressure floor transitions;
* sleep/bedroom candidate location, derived from low-motion long-stay periods;
* room/beacon transitions during awake/moving periods, derived from
  pressure-floor-aware RSSI and supported by ACC.

Together, these results suggest that the Sixth Phase pipeline can provide
behaviour-level metrics rather than only moment-by-moment location estimates.
The pressure signal gives the vertical context, ACC helps separate active and
inactive periods, and RSSI provides the room/beacon-level horizontal context.
